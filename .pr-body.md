## Delegate to Agent (0.15.0)

Long-horizon work without babysitting, in files any runtime can read.

- **Task Beacon: Delegate to Agent…** and tree context *Delegate to Agent (split this)* on task / epic rows.
- With AI configured, the brief is split into 1–6 subtasks by kind: `research` / `analysis` / `implement` / `schedule` (new `plan` kind in `aiClient`, strict JSON reply). Without AI, or if the reply is not JSON, one task is written and the notice says so.
- Finished tasks (`status: done`) in the same wiki with overlapping words are attached as references (`refs:` frontmatter + body excerpt) and fed to the planner so similar work keeps the shape that worked.
- Writes `Projects/<slug>.md` (Epic) + `Tasks/<slug>-NN-<kind>.md` (`category: agent-task`). `schedule` subtasks become `agent-cron` plus a `.task-beacon/jobs.json` row.
- New setting `todoView.agentRunner` (command template with `{file}`, `{title}`, `{root}`) and **Run with Agent** open a VS Code terminal per task and flip `status: in-progress`. Only `agent-task` / `agent-cron` can be handed off; Official / Private never run unattended.
- Refuses to write into the built-in sample wiki; asks for a real wiki folder.
- AGENTS.md documents the delegated-file contract (`kind`, `epic`, `refs`, `## Result`, `done` / `blocked`).

No scheduler is added. Task Beacon writes files and opens a terminal; the runtime is still Hermes / Claude Code / whatever the user sets.

Verified: `tsc --noEmit`, `npm run build`, and an out-of-editor run of `delegateWork` with a stubbed planner (4 subtasks + jobs.json row, references only from `done` files, fallback single task, unique slug on repeat).
